Known bugs
----------
(none known that stop a v6 game from starting)

Fixed: Arthur used to crash on startup, before a single Z-machine instruction
was executed. The cause was that v6 was lumped in with v4/v5 rather than with
v7/v8 in the assembly. make.rb has always treated v6 as a "large" version
(story files up to 512 KB, header file length divided by 8, two high bits of
the block address), using "$zcode_version > 5"; the assembly used the Z7PLUS
flag, which only covers v7 and v8. The damage:
  - disk.asm reserved no space at all for disk_info, so the disk_info the
    boot loader copied in landed on top of the readblocks/readblock code.
    Any v6 game that had to page in a block from disk therefore jumped into
    disk_info as if it were code. Arthur hit this on its very first
    instruction, because its "main" routine unpacks to $010c0c, outside the
    resident part of the story file.
  - vmem.asm gave v6 a vmem_highbyte_mask of $01, not the $03 make.rb had
    already used when building the vmap, so block addresses above $20000
    were misread and the age bits overlapped the address bits.
  - the header file length was multiplied by 4 instead of 8, so Ozmoo thought
    every v6 game was half its real size.
The fix was to use Z6PLUS instead of Z7PLUS at every one of these size
related sites. Z7PLUS is now unused, but is still defined.

Z6 on other targets: deliberately not started
---------------------------------------------
Get z6 working on the C64 first. Nothing is to be done about the other
targets until then, so the following are known and accepted, not oversights:
- The window-local scrolling in screenkernal-z6.asm only covers the code path
  the C64, Plus/4 and MEGA65 share (.s_scroll). The C128 80 column routine
  (.s_scroll_vdc) and the X16 routine (.s_scroll_vera) still scroll the whole
  screen, so a z6 window there will smear the rest of the display.
- ECM (-ecm) is C64 only, and make.rb rejects it elsewhere. The MEGA65 and X16
  don't need it: their video chips give every character its own background
  colour, so those targets should set the window's background directly rather
  than borrowing the ECM approach.
